Tracked docs and agent files (AGENTS.md, SKILL.md, ARCHITECTURE.md, docs/*) carry only structure, rules and commands. Anything about a machine (host aliases, paths, OS quirks, loads), an account, measurements, lessons from runs or "what failed here" is learned by the code and the agent, stored in the private SQLite store, and written out as generated documents in the git-ignored `<repo>/.local/` and `<repo>/.claude.local.md`.

**Why:** the user said "no data hardcode of my pc or the work in docs or agent files; all docs and text files generated by the code agent learning and pc, vps telemetry in a private git ignored". Hosts like `fr1`, paths like `/srv/...` and measurements had been written into AGENTS.md, ARCHITECTURE.md, SKILL.md and a lessons doc.
**How to apply:** add a learning with `bun testing/acceptance.ts note "<text>" --kind gotcha|decision|fact`; probe machines with `telemetry`; regenerate with `docs`; private settings (hosts, paths, published host, checkouts) go in `.local/config.toml`, an overlay of `testing/acceptance.toml`. `bun PRESUBMIT.ts` (private-data check) fails on host paths, user directories, ssh to a host or any literal of the private config in a tracked file. Git history from before this still contains such data (linear history, no rewrite).
